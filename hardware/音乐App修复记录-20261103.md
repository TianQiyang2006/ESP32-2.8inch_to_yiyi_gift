## 7. 追加：用户反馈“持续爆炸声”的根因（2026-11-03 12:30）

用户在现场听到设备持续爆音。排查结论：

- 服务端无关：本机直连 VPS 拉 PCM 实测 498KB/s、MP3 247KB/s，服务器发送正常。
- 设备侧 PCM 吞吐只有约 2.6KB/s（需要 32KB/s）。表现为：缓冲以 2.6KB/s 增长约 10s → 积够 32KB 后一次性播放约 1s → 再等 ~10s，循环往复；音量 40 时听起来就是周期性爆炸声/爆裂声。旧固件（刷机前）串口日志同样存在该模式，因此不是本次播放器改动引入。
- 最可能原因：Arduino 桌面固件默认开启 WiFi modem sleep，在 Windows 移动热点（DTIM 较大）下 TCP 吞吐塌陷；此前音乐固件（小智 app1）显式关闭过省电。

修复：desk.cpp 启动时增加 `WiFi.setSleep(false);`，编译产物 build/music-fix2-20261103（Sketch 7,769,881 字节）。待用户重新连接设备后刷入并用音量 20 做播放速率探针验证；若无效再排查 Windows 热点/ICS 链路。

## 9. 最终修复：PCM 吞吐不足 → μ-law 音频流（2026-11-03 20:00）

排查结论（逐项实测）：
- 设备 PCM 需 32KB/s；修复 WiFi 省电后从 2.6KB/s 提升到约 26KB/s（10 倍），仍差 20%；
- 设备可短时爆发 65KB/s（catalog），但单条持续 PCM 流在该 Windows 热点链路上被限制在 ~26KB/s；AP/STA 同信道、播放时暂停 SoftAP 均无进一步提升（已分别验证后回退）；
- 结论：热点/无线链路对持续流的上下限就在 26KB/s 附近，无法稳定满足 32KB/s。

最终方案：把 PCM s16le（32KB/s）改为 **μ-law 16kHz 单声道（16KB/s）**，链路余量约 60%。
- 服务端 app_http.py **v1.2.0**：ffmpeg 输出 `-f mulaw -ar 16000 -ac 1`；缓存 key 加 `ulaw1` 前缀（旧 s16 缓存自然失效）；track 返回 `codec=ulaw`、`bytes`/`duration_ms` 按 16000 字节/秒计算；Range 不再要求偶数字节（μ-law 无 16bit 帧对齐）。
- 固件：输出任务把 μ-law 字节解码为 16-bit PCM（G.711 标准表）；position/seek/Range 按 16 字节/ms 计算；预缓冲阈值 16384 字节（约 1s）；移除 16bit 奇数字节丢弃逻辑。
- 服务端部署：备份 /root/yiyi-music-backup-20261103-ulaw/，只重启 yiyi-music-app；部署校验 health codec=ulaw、track 640000B/40s、Range 206、0 traceback。
- 固件：build/music-ulaw-20261103/yiyi_desk.ino.bin（7,771,008 字节，MD5 aac8a9b1b6ea43ed36241475ed6219a7），write+verify 通过，只写 app0。

静音实测（音量 0，60s）：**position rate = 999.2 ms/s（1.000x）、underruns 增量 = 0、buffered 充满 262144 后保持满、无 error**。设备已设音量 20 供试听。

代价：音频从 16-bit 无压缩降为 G.711 μ-law（8-bit 压扩），高频细节略降；对 ES8311 小喇叭与礼物场景仍属可听音乐质量。若以后换成更好的网络路径（如手机热点/有线网关），可再切回 16-bit PCM。

## 10. 音质迭代：μ-law → 8kHz/16-bit 线性 PCM（2026-11-03 23:20）

用户试听反馈：μ-law 版“音乐能听出来但沙哑/破音”。分析：服务端 μ-law 数据与源 MP3 相关性 0.9998（内容正确）、固件 μ-law 解码与 ffmpeg 逐样本一致、播放指标 1:1 零 underrun，因此判定为 μ-law（8bit 压扩）本身的量化失真在小喇叭上被感知为沙哑。

改为带宽相同（16KB/s）但**无压扩失真的 8kHz / 16-bit 线性 PCM**：
- 服务端 **v1.3.0**：ffmpeg `-ar 8000 -f s16le`；cache key 前缀 `pcm8k1`；track 返回 `codec=s16le, rate=8000, bytes, duration_ms=bytes*1000/16000`；Range 恢复 16bit 偶数字节对齐。
