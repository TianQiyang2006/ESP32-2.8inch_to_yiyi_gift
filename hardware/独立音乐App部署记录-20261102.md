# 独立音乐 App

本次范围是桌面内独立的音乐软件。小智 AI 的恢复、语音质量及原有 MCP 音乐工具的调整暂缓；本次不写 app1、模型或分区表。

## 界面与操作

- 采用 `design/vps-music-app-20261102/v2` 定稿，第二页应用按 2×2 排列：闹钟、番茄时钟／音乐、俄罗斯方块。
- 音乐主界面提供上一首、播放／暂停、下一首、播放模式、进度拖动和音量面板。
- 播放列表点击右下列表图标或歌单名称后打开；点击歌词打开歌词页，返回箭头逐层返回。
- 右上角音量图标与数值分别定位，留出间隔；音乐首次音量为 40，保存在独立的 `desk-music/volume` 中。
- 允许返回桌面后继续播放；进入现有小智应用前停止独立音乐，避免两个程序同时使用音频。

## VPS

新增 `/opt/yiyi-music/app_http.py` 和 `yiyi-music-app.service`，使用 2244 端口；2233 原服务及其他运行服务保持原配置。

新接口沿用既有私有路径，不在本文记录凭据或完整 URL：

| GET 路径 | 用途 |
|---|---|
| `/health` | 健康状态 |
| `/<private>/app/catalog` | 歌曲和完整歌单 |
| `/<private>/app/track/<id>` | 时长、PCM 地址和已有歌词地址 |
| `/<private>/app/pcm/<id>` | 支持偶数字节 Range 的音频流 |

VPS 用既有 `/opt/yiyi-music/bin/ffmpeg` 将本地曲库转换为 16 kHz、单声道、16 位 PCM，缓存上限 1 GiB。设备使用 256 KiB PSRAM 缓冲，起播预缓冲约 1 秒，通过既有 ES8311 播放。服务器限制 CPU 40%、内存 192 MiB。

播放器直接读取现有曲库和歌单，不依赖小智 MCP 调用来控制播放。当前支持最多 200 首歌曲、8 个歌单，界面显示前两个歌单；现有曲库 134 首，歌单分别为 131 首和 3 首。

## 构建、备份与验证

固件版本 `0.9.0-music-app`，Arduino ESP32 core 2.0.17。保留 app0 的 7.5 MiB 大小与原始分区布局。

构建输出：`build/independent-music/`。最终编译日志：`build/independent-music-final-compile.log`。

写入前备份在 `build/backups/before-independent-music-20261102/`：

- `desktop.bin` 已用设备端完整摘要核对通过。
- `boot-nvs-ota.bin` 为已逐段验证读取的前 64 KiB，包含 NVS 和分区表。
- `littlefs.bin` 为单独读取的完整文件系统。
- `manifest.json` 记录有效备份的哈希。`flash-16mb.part` 是未完成的整片读取，不作为恢复镜像。

刷写地址只有 `0x10000`。最终镜像 7,768,576 字节，SHA-256：`30a059b1f860836878653ceee3d37fde818043fee20d70ee47de8ea7fcd0ac26`。

本地原生 LVGL 验证：`python hardware/scripts/test_native_lvgl.py --music --out build/music-host/screens`。验证 2×2 位置、音量图标间距、列表默认隐藏、暂停续播、切歌、音量预设、歌词页、进度滑条输入保护及 40 次覆盖层重建。

VPS 实测已验证 134 首曲目、131+3 歌单 ID 全部有效，PCM、206 续传、416 非法范围和真实歌词；原有音乐、frpc、gost 服务仍运行。

设备验证结果与截图在 `build/independent-music-device/`；烧录与设备端摘要日志在 `build/independent-music-flash*.log`。听感以设备实际试听为准。
