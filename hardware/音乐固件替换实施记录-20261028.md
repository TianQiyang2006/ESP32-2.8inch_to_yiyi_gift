# 音乐固件替换实施记录（2026-10-28/29）

- 目标：把双应用布局里的 **app1（原官方小智 2.5.0）** 替换为 [Maggotxy/xiaozhi-esp32-music](https://github.com/Maggotxy/xiaozhi-esp32-music)（基于上游 v1.8.5 + 音乐/歌词/频谱）。
- 结论：**替换已完成并烧录验证**。设备当前启动桌面 app0；app1 为音乐小智 `2.5.0-music`，桌面已识别为已安装，可从桌面进入、右上角“退出”可返回桌面；离线可启动、串口诊断与音乐服务地址配置可用。
- 未完成验证：受本机网络环境限制（只有 5 GHz 热点/Windows 热点转发不稳定），**Wi-Fi 联网、语音云链路、真实音乐播放未实测**；这些需要在 2.4 GHz 路由器 + 用户 VPS 环境复测。

## 2. 改动与源码归档

移植后的完整源码在 [`hardware/esp-idf/yiyi_music/`](../esp-idf/yiyi_music/)，改动清单见其 [`PORTING.md`](../esp-idf/yiyi_music/PORTING.md)。要点：

- 新增 `yiyi-es3c28p` 板型（ILI9341 320×240 自定义初始化、FT6336G 触摸 + NVS 仿射、ES8311、右上角“退出”按钮、USB 串口诊断）。
- 双应用桥接：启动时从桌面 NVS 导入 Wi-Fi/UUID；退出时切回 app0 并写 `yiyi-desk/voiceReturn`。
- 桌面 Wi-Fi 模式：app1 不启动 AP 配网；离线时 15 s 超时后继续启动，不再阻塞。
- 关闭固件 OTA 升级动作（保留 CheckVersion 以获取协议/激活配置），避免写入 app0。
- 工程版本 `2.5.0-music`，project_name 仍为 `xiaozhi`，桌面据此识别安装。
- 音乐服务地址可配置：NVS `music` / `server_url`，串口命令 `musicurl <url>`，`musicurl default` 恢复默认。
- 修复了两个 fork 原有问题（在本板暴露）：离线时 `WifiStation::GetRssi()` 内 `ESP_ERROR_CHECK` 导致 panic 重启；`printf` 使用 `%llu` 在 newlib nano 下崩溃。

## 4.1 2026-10-29 用户反馈“小智状态不对/无法连接服务器”的现场诊断

- 现场实测：app1 正在运行，Wi-Fi 已连（`qingyu` 热点，IP `192.168.137.216`，RSSI -33），`status` 显示 `state=3`（idle）、`wakeWordRunning=true`、`music=true`、`musicUrl=http://110.42.59.54:2233`。
- 云端链路：启动日志显示 `MQTT: Connecting to endpoint api.tenclass.net` → `Certificate validated` → `MQTT: Connected to endpoint` → `STATE: idle`；唤醒模型 `wn9_nihaoxiaozhi_tts` 成功加载。
- 结论：**语音服务器链路当前是通的**。用户看到的“无法连接服务/无法连接服务器”更可能来自：①本机测试用 Windows 热点（由 5 GHz YNU 转发）不稳定导致 Wi-Fi 短暂掉线时的提示；②在桌面点“小智”时 Wi-Fi 尚未就绪导致未能切换；③真实语音对话的 audio channel（UDP/TLS）尚未实测，若被服务端拒绝会提示无法连接；④点歌提示失败则是原作者音乐服务器已停服，与语音服务器无关。
- 证据：`build/eval/app1-cloud-capture.log`、`build/eval/app1-status-final.txt`、`build/eval/diag-current.txt`。

## 5. 未验证 / 已知限制

1. **Wi-Fi / 语音云链路未实测**：本机可用热点只有 5 GHz（ESP32-S3 仅 2.4 GHz）与不稳定的 Windows 热点转发；桌面和 app1 均未能稳定联网。需在用户家里的 2.4 GHz 路由器上验证：桌面连 Wi-Fi → 进入小智 → 唤醒词/对话；若 `xiaozhi.me` 对 1.8.5 客户端不兼容，需要回滚或改用官方 2.5.0。
2. **真实音乐播放未实测**：需要用户 VPS 按 [`hardware/音乐服务接口约定.md`](../音乐服务接口约定.md) 提供接口。建议 MP3 为 **16 kHz 单声道**，避免固件切换 I2S 采样率时 ES8311 变调/与唤醒词双工冲突。
3. **音频听感/ES8311 采样率切换**：未听感验证；当前默认服务端给 16 kHz 时最稳。
4. **频谱显示**：fork 的 `lcd_display.cc` 绘制宽度硬编码 240 px，在 320×240 屏上只占左侧 240 px（不影响功能）。
5. **歌词字体**：fork 字体为内置子集，生僻字可能缺字；需要时后续做字体覆盖。
6. **触摸校准契约**：桌面新校准写两点 `calx0..caly1` 并清 `affok`；app1 仍只读旧仿射 `affax..affcy`。当前设备用的是旧仿射，若在桌面重新校准，app1 触摸可能不准（后续可补）。
7. **音乐播放行为**：fork 只在 idle 出声，任何语音/状态切换会停播且不续播（上游行为）。

## 7. 下一步（用户操作）

1. 在设备桌面设置里连接家里的 **2.4 GHz Wi-Fi**，从“全部功能 → 小智”进入，确认能唤醒/对话；这一步会验证 `xiaozhi.me` 对 1.8.5 客户端的兼容性。
2. 在你的 VPS 上实现 [`音乐服务接口约定.md`](../音乐服务接口约定.md) 的 `/stream_pcm`，提供 16 kHz 单声道 MP3 + 可选 LRC。
3. 设备 app1 串口（USB 115200）执行 `musicurl http://<vps>:<port>`（掉电保存），然后 `music 晴天` 验证播放，再测语音点歌（需在 xiaozhi.me 后台按原作者说明配置 DeepSeekV3 + 提示词）。
4. 若语音点歌/播放不达预期，随时可用回滚脚本恢复官方 2.5.0。
