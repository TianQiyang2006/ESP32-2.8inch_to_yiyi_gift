# 音乐破音修复 · 2026-11-04

用户反馈：沙哑、破音或杂音。本轮修复桌面独立音乐 App 的真实音频输出链路。

## 确认的原因

`audio_board.cpp` 将 ES8311 的 DAC 音量寄存器 `0x32` 设置为 `0xff`。
Espressif `esp_codec_dev` 的 ES8311 驱动给出的音量范围为：
寄存器 `0x00` = −95.5 dB，`0xff` = +32 dB，每格 0.5 dB。
因此原设置不是单位增益，而是将软件音量处理后的信号再放大约 39.8 倍。
即使界面设置为 20%，超过原始满幅约 12.6% 的采样也会超出数字增益后的满幅范围。
该错误可以解释正常播放速率、没有缓冲耗尽时仍持续破音的现象。

原固件已有的有符号音量缩放和 32 kHz IMA ADPCM 解码保留。
此前将音质问题归因于 μ-law 编码的记录不能排除当时同样存在的 DAC 增益错误。

## 修改

- DAC 寄存器改为 `0xbf`，即 0 dB 单位增益。界面百分比不变，实际响度会低于原先被过度放大的输出。
- 按 Espressif 的 256× MCLK 时钟表，16 kHz 使用 DAC OSR `0x20`，32 kHz 使用 `0x10`；启动和运行中切换均更新。原代码在 16 kHz 下也固定为 `0x10`。
- 切换采样率前关闭功放；提示音在时钟配置完成后重新启用功放。
- I2C/时钟配置失败、I2S 写入失败或只写入部分数据时停止输出并报告错误，避免反复重送样本或无提示停在播放态。

音频仍为服务端提供的 32 kHz、单声道 IMA ADPCM；不通过降低采样率解决失真。
共享音频芯片的增益修正也会降低木鱼和提醒音在原百分比下的实际响度，各应用保存的音量数值保持不变。
