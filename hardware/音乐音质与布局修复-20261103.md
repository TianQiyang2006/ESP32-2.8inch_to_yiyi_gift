# 音乐音质与布局修复（2026-11-03）

本记录接续《音乐App修复记录-20261103.md》，后续的 32 kHz 方案取代其中的
8 kHz 线性 PCM 试听方案。最终烧录和实机结果在完成后追加。

## 原因与修改

- 确认一处直接破音缺陷：`int32_t(samples[i]) * percent / 100` 中 `percent`
  是 unsigned，负半波被转换成无符号并作除法，写回 int16_t 后失真。改为复用
  `ToneSynth::applyMaster` 的有符号缩放，校验音量 40 时正负采样和满幅值。
- 8 kHz 音源只能保留约 4 kHz 以内的声音，且固件简单重复样本上采样，音乐
  高频和细节明显缺失。低带宽方案消除了部分网络压力，但音质不满足音乐播放。
- 新增可选 `?format=ima32` 接口：32 kHz、单声道、IMA ADPCM，1024 字节一块，
  每块 2041 个采样，约 16.05 KB/s。与旧版的 16 KB/s 接近，保留更宽频段。
- 固件按独立块解码到 16-bit PCM，以真正的 32 kHz I2S 输出，不再重复 8 kHz
  样本。MCLK 与采样率保持 256 倍；闹钟、番茄时钟、提示音仍使用 16 kHz。
- 拖动进度按块对齐，最大向前偏差约 64ms；暂停保留块内游标，继续播放不丢失
  解码状态。网络断流仍使用 Range 恢复传输。
- 旧 8 kHz 接口和缓存保留，只有独立音乐服务 `yiyi-music-app.service` 重启。
  其他服务配置与进程未改变；小智 app1 和分区布局未修改。
- 所有单行标题固定为字体行高，防止英文长歌名换行侵占歌手行。列表标题为
  “播放中”提示留出间距，歌词页标题与歌手之间留出间距；音量图标与数字分开。

## 已完成验证

- 服务端 33 项单测通过，包含旧格式兼容、新格式元数据、独立缓存、Range 和 HEAD。
- 真实 VPS《晴天》返回 32 kHz / IMA ADPCM，数据块头、长度、Range 206 正常，
  同时旧请求仍返回 8 kHz / s16le。曲库 134 首、两个歌单保留。
- 原生解码器将 6 kHz 正弦测试流的 32,656 个采样与 FFmpeg 的输出逐个比较，
  全部一致；无效块头被拒绝，独立块跳转通过。
  同一批采样的音量 40 缩放也与 int64 参考计算逐个一致。
- 《晴天》约 30 秒参考比较：相对 32 kHz 原始解码音源，ADPCM 信噪比约 35.98dB，
  RMS 6532.9 / 6534.8。此项只证明数据转换质量，不代表小喇叭的实际听感。
- LVGL 主机验证通过：2×2 排序、默认隐藏歌单、暂停续播、切歌、音量、歌词、
  40 次弹层重建、长英文标题与歌手行分离；共生成七张截图。
