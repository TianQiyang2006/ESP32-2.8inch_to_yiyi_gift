# FM 与音乐列表触摸修复 · 2026-11-14

本轮处理在线 FM 的选台列表、音乐的播放列表在滑动后无法选择内容或返回的问题。修复版本为 `0.19.1-media-picker`，以 `0.19.0-online-fm` 为基线，修改共享触摸防误点逻辑及 FM 页面重建条件。本文独立记录此次修复；在线 FM 首次实现、旧镜像及旧部署结果继续保存在 `hardware/在线FM实现与验证-20261114.md` 与原部署目录。

修复已完成主机验证、正式构建、镜像核验和 app0 部署。COM8 上的新版完整应用摘要校验通过，串口模拟触摸实机检查的 75 项检查全部通过；最终两个播放器均已停止。物理手指触摸与扬声器人工试听不在本轮验证范围。

## 问题与根因

触摸驱动在 release 的 `read_cb` 内先向 `desk.cpp::onTouchGesture()` 报告手势，再由 LVGL 消费同一份释放采样。此前，位移任一轴超过 32 px 就调用 `lv_indev_wait_release()`，用于阻止拖动结束时误点卡片、列表行或键盘。

在 LVGL 8.4 中，对已经开始滚动的输入调用这一函数，会产生以下状态链：

1. `lv_indev.c::indev_proc_release()` 的等待释放分支发送 `PRESS_LOST`，清空 `act_obj` 和 `last_obj`，但保留 `scroll_obj`。
2. 如果用户在惯性滚动结束前再次按下，LVGL 因 `last_obj == nullptr` 跳过停止旧惯性的正常分支。
3. 初始化新按下对象时，LVGL 将 `scroll_dir` 重置为 `LV_DIR_NONE`，遗留的 `scroll_obj` 仍非空。
4. `lv_indev_scroll.c::_lv_indev_scroll_throw_handler()` 遇到 `LV_DIR_NONE` 直接返回，无法执行末尾清空 `scroll_obj` 的逻辑。
5. 后续释放时，LVGL 继续将输入视为滚动操作，因 `scroll_obj != nullptr` 跳过 `CLICKED`。这会同时影响列表行、顶部返回及其他依赖点击事件的控件。

该问题位于两个 App 共用的输入路径，不能只通过调整选台或歌曲行回调解决。针对性主机回归已用真实 LVGL 指针采样复现：旧实现的四个“滚动后立即点返回／列表行”场景均留下 `scroll_obj=1, scroll_dir=0`，再等待一秒仍无法点击。

刚完成列表重建、尚未发生滚动时的行点击和返回在回归中正常；`desk.cpp::render()` 已调用 `lv_indev_reset()`，回归也确认完整重建会清除上一视图的滚动归属。因此，已证实的触发条件是滚动释放与下一次按压的时序，不能把所有“刚进入列表就无响应”的描述都直接归因于上一页面遗留状态。

## 旧固件的实机复现

COM8 上实际运行的 `0.19.0-online-fm`（镜像 MD5 `8f5167ca63fef8c4311f1a787a32aee3`）已通过串口模拟输入复现同类故障。证据为 `build/media-picker-fix-20261114/before/reproduction.json`。其 `passed: true` 表示故障复现成功，不是产品验收通过。

复现顺序为进入 App、打开列表、发送 `swipe 140 177 140 90`，等待 0.4 秒后发送 `tap 20 18`，再等待 0.7 秒发送 `tap 140 141`。FM 和音乐均在返回及行点击后停留列表：FM 截图为同目录的 `rapid-scroll-back.png`、`rapid-scroll-row.png`、`rapid-scroll-command-back.png`，音乐截图为 `music-rapid-back.png`、`music-rapid-row.png`。较慢、留有间隔的普通点击在初始 `probe-statuses.json` 检查中可用。

实机截图证明两个列表在该输入序列下无响应；内部 `scroll_obj` 状态链由独立主机回归确认。此项使用串口模拟触摸，未将其记录为物理手指测试，也未据此声称首次构建列表就必现故障。

## 修改范围与防误触边界

| 文件 | 修改 | 作用 |
| --- | --- | --- |
| `hardware/arduino/yiyi_desk/src/touch.h` | 增加 `Touch::suppressSwipeClick()` | 超过原有 32 px 阈值且没有 LVGL 滚动对象时才调用 `lv_indev_wait_release()` |
| `hardware/arduino/yiyi_desk/desk.cpp` | 在原防误点位置调用该函数 | 已进入滚动的输入交由 LVGL 正常处理释放与惯性结束 |
| `hardware/arduino/yiyi_desk/src/pages/radio_page.cpp` | `inputActive()` 增加 `view == builtView` | 已请求切换本地视图时，旧列表的滚动状态不再阻止重建；与音乐页已有保护一致 |
| `hardware/arduino/yiyi_desk/board_config.h` | 版本改为 `0.19.1-media-picker` | 区分修复镜像与旧版 FM 镜像 |

以上四个生产文件的变化已与已安装 `0.19.0` 的已核验构建源码副本比较，记录在 `build/media-picker-fix-20261114/production-changes.json`，完整补丁为同目录 `production-changes.patch`。

已有滚动对象时，LVGL 在释放处理开始保存 `scroll_obj`，仅在它为空时才发送 `SHORT_CLICKED/CLICKED`，随后才处理惯性。因此保留正常释放不会把列表滚动变成选台或选歌，同时保留下一次按压所需的对象状态。

没有进入 LVGL 滚动的大幅移动继续沿用原防误点行为；新比较表达式与原 `abs(dx) > 32 || abs(dy) > 32` 等价。游戏的提前返回、转场限制、左右翻页和边缘返回的路由顺序保持一致。LVGL 滑块自身清除滚动及滚动传递标志，普通滑块拖动继续走原来的非滚动路径；现有设置页对 `RELEASED` 与 `PRESS_LOST` 均能释放输入占用。只读审查未发现此次修改新增的可行动问题。
