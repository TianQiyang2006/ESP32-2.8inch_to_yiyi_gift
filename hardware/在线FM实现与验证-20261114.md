# 在线 FM 实现与验证 · 2026-11-14

本轮按用户要求在现有桌面增加在线 FM，先完成 UI、离线构建及验证，用户批准后已刷入并进行实机验证。当前版本号为 `0.19.0-online-fm`，保留此前倒数日和其他应用的编号与入口顺序；在线 FM 追加到全部应用第四页。

## 功能与界面

使用现有 LVGL 8.4 的 320×240 横屏、字库和音频驱动。奶油纸底、墨绿收音机卡片、扬声器刻线和琥珀色直播状态全部用代码绘制，没有增加位图素材。

支持选台、上一台／下一台、播放／停止、全部／收藏列表、0–100% 独立音量、静音／20／40 快捷档，以及离线、缓冲、重连和保存失败提示。收藏、最近电台和音量写入独立 NVS 名称空间，记录带版本与 CRC，按稳定电台 ID 恢复。开机或仅打开应用不会自动出声；手动播放后离开页面可继续收听。默认六台为北京音乐广播、动感101、经典947、广东音乐之声、中国之声、北京新闻广播。

实际 UI 截图与可点击预览在 `design/online-fm-20261114/index.html` 和 `build/online-fm-20261114/ui/`。预览里的节目文字是主机状态示例；最终设备请求使用 `Icy-MetaData: 0`，默认不请求节目元数据，没有元数据时使用普通陪伴提示。ICY 解析器和真实元数据显示能力仍保留。

## 播放实现

设备直接访问公开 HTTP／HTTPS 电台，不依赖新增 VPS 转码服务。最终默认六台使用 HTTP MP3 连续流，HTTP/1.1 请求使用 `Icy-MetaData: 0`；数据先去除 HTTP chunked 帧，再去除源可能返回的 ICY 元数据，交给 Helix MP3／AAC 解码器。HTTPS 接入能力仍保留。M3U8／HLS 播放列表不在本次轻量实现范围内，收到不支持的内容会显示错误。

解码器从 ESP8266Audio 1.9.9 的固定归档提取，归档 SHA-256、原始与适配后文件哈希保存在 `src/radio_vendor/manifest.json`。`hardware/scripts/vendor_radio_audio.py` 可重建依赖；保留上游 GPL 与 Helix RPSL／RCSL 许可文本。没有引入第二套 I2S 驱动。解码工作区、PCM 缓冲、64 KiB 网络环形缓冲与 64 KiB 线性解码输入放 PSRAM，压缩缓冲合计 128 KiB。core 0 的两个后台任务分别负责网络接收（优先级 2、4096 B 栈）和解码／PCM 输出（优先级 3）；网络单次读取最多处理 2048 B 原始数据，并检查约 2 ms 时间预算。停止、取消或提醒抢占时先取消并等待接收任务退出，再关闭连接及释放会话资源。

首次开始播放前蓄满 49,152 B（48 KiB）；播放期间压缩输入不足 2048 B 时暂停供音，重新蓄至 16,384 B（16 KiB）再继续，接收无数据超时为 15 秒。进入解码前重置进度看门狗，避免将等待缓冲的时间计入解码失败。此策略用于吸收直播突发和抖动；当前证据尚未确定早期断续的唯一根因。

输入经双声道混合、低通滤波和相位连续的有理重采样，转换为现有 ES8311 支持的 32 kHz 单声道输出。`AudioBoard` 为音乐和 FM 管理独立来源：旧任务不能在新播放器取得扬声器后继续输出或将其静音。显式媒体切换与音乐自动 EOF／重试共用控制锁，并核对播放代次，避免旧音乐后台任务抢回 FM。闹钟、番茄钟、倒计时等提醒保留优先级，FM 在提醒结束后重新接入直播。

可选 HTTPS 路径使用加密连接但不校验服务器证书，与早期桌面网络源测试中验证证书的方式不同；最终默认 HTTP 源不经过 TLS。默认源的地址以后可能变动；当前固定电台表集中在 `src/radio_station_data.h`，未来可更新该表。所有默认源共用蜻蜓 CDN，因此六个地址不代表六个独立上游。

## 已完成的软件验证

- `verify_radio_ui.py`：生产 LVGL 页面，2125 项检查、18 张截图、40 轮页面生命周期；真实指针操作覆盖选台、滚动取消误点、收藏、音量、返回、离线与错误。播放器为仅主机使用的状态数据。
- `test_native_lvgl.py --music`：现有音乐页面交互回归，以及真实全部应用第四页进入 FM、列表返回和离开页面保留播放状态；11 张截图。后台音频为主机替身，不代表实机收听。
- `run_host_regression.py`：现有数据、导航、手势、游戏规则、天气、面板、音频、音乐记忆等主机回归通过。
- `test_audio_output.py`：编译真实 `audio_board.cpp` 并捕获 I2C／I2S 操作；验证旧任务的写入／清理不会影响新媒体来源，以及提醒优先级。
- `test_radio_audio.py`：编译真实 Helix 解码器；验证 chunked／ICY、七种输入采样率的输出数量和抗混叠；真实 44.1／48 kHz 中文电台 MP3 样本解码及 16／44.1／48 kHz AAC 样本参考比较通过。AAC 与 FFmpeg 参考输出的信噪比约 65.9–75.2 dB。真实截取 MP3 样本存在开头储备池不足／结尾不完整帧，报告保留错误数量，没有将其描述成零错误。
- 早期桌面网络测试对默认六台分别读取同一 HTTPS 连接中的两段 32 KiB，并验证连续 MP3 帧；证据在 `design/online-fm-20261114/stations-verification.json`。这是默认源改为 HTTP 之前的证据，不代表最终固件六台实机收听全部通过。

固件使用现有 Arduino ESP32 core 2.0.17-cn／ESP-IDF 4.4 工具链，编译与最终镜像证据保存在 `build/online-fm-20261114/`。`verify_radio_firmware.py` 检查全部源码构建副本、编译对象、UI 源码哈希、app0 容量、ESP32-S3 镜像校验和与验证哈希。

最终增量构建于 2026-11-14 12:10（北京时间）完成，版本为 `0.19.0-online-fm`。一致性检查通过：核对 499 个源码／配置文件、373 个编译单元，导出镜像与构建目录中的镜像 SHA-256 相同，镜像含当前版本字符串，UI 源码与已验证截图的哈希一致。ESP32-S3 镜像校验和与验证哈希均有效。最终镜像 MD5 为 `8f5167ca63fef8c4311f1a787a32aee3`，SHA-256 为 `06702e9ad11fca324b924faa0cca0866d2e65c5c4844a323dd96609312fbfb31`。

## 最终部署与实机结果

用户批准后已刷入上述最终镜像。刷入前保存完整 16 MiB 备份 `build/online-fm-20261114/deployment/before/full-16mb.bin`；最终更新只写入 app0 变化扇区，并对完整 7,946,448 B 应用镜像独立回读校验，通过记录在 `build/online-fm-20261114/deployment/buffer-watchdog-delta.log`。部署汇总为 `build/online-fm-20261114/deployment/deployment-verification.json`。

最终镜像上的电台遍历报告 `deployment/device/stations-20261114-121443/verification.json` 中，北京新闻广播、北京音乐广播、动感101、经典947各完成约 15 秒测试并达到脚本吞吐要求；广东音乐之声在测试中发生缓冲，平均约 24,847 PCM 样本／秒，未通过要求，因此该遍历报告整体为失败。中国之声另在 `deployment/device/soak-20261114-121839/verification.json` 通过 60.081 秒解码输出检查，平均约 31,258 PCM 样本／秒，并确认停止后播放状态清除、任务退出、PCM 计数停止和无关设置保留。该次测量开始和结束时解码错误累计值均为 15，报告保留启动阶段已有错误，没有将其写为零错误。以上 `deployment/` 均相对于 `build/online-fm-20261114/`。

最终镜像上的完整操作检查 `deployment/device/smoke-20261114-122153/verification.json` 通过：打开不自动播放，约 8.1 秒播放的 PCM 吞吐为 31,996 样本／秒，覆盖音量、收藏切换与恢复、全部／收藏列表、返回、后台播放和停止后任务回收。同目录保留准备收听、播放、20% 音量、列表及收藏的设备截图。`deployment/device/reminder-20261114-122229/verification.json` 通过真实 3 秒倒计时试听抢占与恢复检查，没有保存计时器草稿。`deployment/device/final-20261114-122318/verification.json` 确认最终版本／镜像一致、无关原设置保持、FM 已停止且任务退出；FM 音量保留 20%。

吞吐计算使用设备 `uptimeMs` 的相邻有效状态，读取前清空串口遗留输入；较早测试中存在旧 USB 状态回复使主机计时与设备计数不对应的测量问题。最终上述报告已修正该问题，早期真实的断流、缓冲与广东音乐之声失败记录仍保留。

部署报告采样中，播放及提醒切换期间观察到的最小空闲内部堆为 20,376 B，最小空闲 PSRAM 为 7,733,503 B；最终停止时分别为 78,184 B 和 7,908,399 B。这些是串口状态采样值，不是连续测量得到的绝对内存峰值。

五台达到上述有限时长检查要求，不构成默认六台长期稳定或完全无卡顿的结论；广东音乐之声的缓冲问题保留在结果中。PCM 计数、设备截图和串口状态不等同于扬声器录音或人工听感验收。早期主机验证继续只证明其各自的软件范围。
