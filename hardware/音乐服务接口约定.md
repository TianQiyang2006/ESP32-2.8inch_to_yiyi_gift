# 音乐固件服务端接口约定（VPS 点歌接口）

> 适用固件：`yiyi-es3c28p` 音乐小智（基于 [Maggotxy/xiaozhi-esp32-music](https://github.com/Maggotxy/xiaozhi-esp32-music)，上游 v1.8.5 + 音乐/歌词/频谱改动）
> 设备侧默认地址：`http://110.42.59.54:2233`（原作者已停服的服务器）
> 本文定义**你自己的 VPS 需要实现的最小接口**；设备地址可在串口里改，无需重新编译。
> 设备端已实测：`musicurl` 保存/恢复与 `status` 读取生效；`music` 在服务不可达时输出 success=0 且设备不崩溃（真实播放待 VPS 就绪后验证）。

## 0. 设备地址如何配置（不重新编译）

音乐模块每次点歌都会读 NVS：

- namespace `music`，key `server_url`，值如 `http://1.2.3.4:2233`（不要以 `/` 结尾）
- 串口（USB，115200，app1 的 `desktop_diag` 控制台）命令：
  - `musicurl http://1.2.3.4:2233` —— 保存新地址（掉电保存，立即生效）
  - `musicurl default` —— 删除覆盖，恢复内置默认地址
- 也可在编译时改 `main/boards/common/esp32_music.cc` 里的默认值。

## 1. 查询端点

```
GET http://<your-vps>:<port>/stream_pcm?song=<url-encoded 歌名>&artist=<url-encoded 歌手>
```

设备发出的请求头（服务器**可以忽略**，也可用于简单鉴权）：

| Header | 值 |
| --- | --- |
| `User-Agent` | `ESP32-Music-Player/1.0` |
| `Accept` | `application/json` |
| `X-MAC-Address` | 设备 Wi-Fi MAC |
| `X-Chip-ID` | 芯片 ID |
| `X-Timestamp` | 设备**开机秒数**（`esp_timer`，不是墙钟时间） |
| `X-Dynamic-Key` | `SHA256(mac:chip_id:timestamp:secret)` 前 16 字节大写十六进制；`secret` 在固件里硬编码为 `your-esp32-secret-key-2024`（仅演示级，可忽略） |

## 2. 成功响应（HTTP 200，`application/json`）

```json
{
  "artist": "周杰伦",
  "title": "晴天",
  "audio_url": "http://<your-vps>:<port>/media/qingtian.mp3",
  "lyric_url": "http://<your-vps>:<port>/lyrics/qingtian.lrc"
}
```

- `audio_url`：必填，设备只检查是否以 `http` 开头；建议同域名直链。
- `lyric_url`：可空/可省略（没歌词只影响歌词模式）。

## 3. 音频与歌词要求

### 3.1 音频（关键）

- 格式：**MP3**（固件用 Helix 定点解码器）
- **采样率：16 kHz；声道：单声道**（强烈建议，音乐质量可接受且最稳）
  - 原因：设备 ES8311 codec 固定 16 kHz。非 16 kHz 时固件会切换 I2S 时钟，但 ES8311 寄存器未重配，可能变调/失真；且 I2S 是双工（唤醒词一直用麦克风），改时钟会影响语音。
  - 如果一定要 44.1 kHz：后续固件需加软件重采样（44.1 k→16 k）后再进 codec；当前版本不建议。
- 建议码率 32–64 kbps；支持 `Range: bytes=0-`，返回 200 或 206 均可。
- 服务端最好支持 `Accept-Ranges` 与流式输出，避免整首缓冲。

### 3.2 歌词（可选）

- `lyric_url` 返回 UTF-8 LRC 文本：
  ```
  [ti:晴天]
  [ar:周杰伦]
  [00:12.34]故事的小黄花
  [00:16.78]从出生那年就飘着
  ```
- 设备按 `[mm:ss.xx]` 解析并逐句显示；不支持滚动/多行特殊格式。
- 注意：设备内置中文字体是**子集**，歌词生僻字可能缺字（后续可通过自定义字体解决）。

## 4. 失败与边界

- 返回非 200、JSON 无 `audio_url`、或连接失败 → 设备提示「获取音乐资源失败」。
- 设备只在 `Idle` 状态出声；播放中一旦语音唤醒/说话/触摸切状态就会停播（固件原有行为），不会自动续播。
- 设备端 HTTP 客户端**不支持现代 TLS 特性**（上游 v1.8.5 的 esp-tls 较旧）；建议 VPS 用 **HTTP**（局域网/公网端口直连），HTTPS 需实测。

## 5. 最小 Flask 示例（可直接部署）

```python
from flask import Flask, request, jsonify, send_from_directory

app = Flask(__name__)
BASE = "http://1.2.3.4:2233"

@app.get("/stream_pcm")
def stream_pcm():
    song = request.args.get("song", "")
    artist = request.args.get("artist", "")
    # TODO: 在你自己的曲库/对象存储里按 song 找文件
    return jsonify(
        artist=artist,
        title=song,
        audio_url=f"{BASE}/media/{song}.mp3",
        lyric_url=f"{BASE}/lyrics/{song}.lrc",
    )

@app.get("/media/<path:name>")
def media(name):
    return send_from_directory("/srv/music", name, mimetype="audio/mpeg")

@app.get("/lyrics/<path:name>")
def lyrics(name):
    return send_from_directory("/srv/lyrics", name, mimetype="text/plain")

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=2233)
```

转 16 kHz 单声道 MP3 示例（ffmpeg）：

```bash
ffmpeg -i input.mp3 -ac 1 -ar 16000 -b:a 48k output.mp3
```

## 6. 设备侧测试方法（无语音、不依赖 xiaozhi.me 工具配置）

USB 串口 115200，确认当前是 app1（`status` 返回 `"implementation":"music-2.5.0"`）：

| 命令 | 作用 |
| --- | --- |
| `musicurl http://<vps>:2233` | 保存服务器地址 |
| `music 晴天` | 绕过语音，直接调用一次点歌；设备回 `MUSIC_START` / `MUSIC_RESULT` |
| `musicstop` | 停止播放 |
| `musicmode lyrics` / `musicmode spectrum` | 切换歌词/频谱显示 |
| `status` | 查看 Wi-Fi、状态、音乐对象与当前 `musicUrl` |
| `help` | 列出全部诊断命令 |

> 语音点歌还依赖 `xiaozhi.me` 后台：按原作者说明，把设备角色配置成 DeepSeekV3，并在人物介绍里写明「收到音乐相关需求时，只使用 MCP tool `self.music.play_song`，禁止使用 `search_music`」。否则模型可能走官方（少量歌曲）的 `search_music`，不调用本接口。
