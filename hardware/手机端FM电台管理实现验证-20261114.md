# 手机端 FM 电台管理

本次为 `0.19.2-radio-manager` 增加手机设置页的电台管理。设备当前安装的版本仍为上一轮列表触摸修复版 `0.19.1-media-picker`。本轮只完成代码、界面预览、主机测试与固件构建，未打开串口、未刷入；按用户此前“做好 UI 设计，和我确认之后再刷入”的要求，等待界面确认。

## 使用方式和行为

手机连接设备热点后，进入原有设置页，找到“我的电台”。默认保留 6 个中文音乐／综合广播电台，总数上限为 20 个，默认台同样允许编辑、删除，也可以全部删除。

添加和编辑填写电台名称、分类标签、音频直播地址。名称和分类各最多 24 字，分类可留空；地址最多 512 字节，支持 HTTP／HTTPS 的 MP3、AAC 直播直流。不支持将电台网页、HLS／m3u8 或其他播放列表作为音频源。保存只更新目录，需在设备上选台后播放。

- 编辑名称或分类时，保留当前播放和收藏。
- 编辑正在播放电台的网址时，重新连接该电台。
- 删除其他电台时，当前播放和收藏通过稳定 ID 保持对应关系，不随列表索引变化。
- 删除当前电台时停止播放，选择剩余第一台，等待用户手动开始。
- 删除全部电台时显示空态，允许正常返回；手机新增后恢复选台。
- 保存完成后在 LittleFS 保留电台目录，重启后恢复，包括零电台状态。

## 手机界面

采用与设备 FM 一致的奶油色、墨绿和琥珀配色。显示已保存数量、名称、标签、地址，每条提供编辑和删除。新增表单在列表下方，删除需要在页内确认。满 20 台时禁止新增，仍可编辑、删除。

未保存的草稿不会被轮询刷新覆盖；提交期间的后续修改保留为草稿。发生版本冲突时保留草稿，要求用户刷新核对后重试。读取存储警告时展示原因；目录不可用、版本为零时禁止写入，允许刷新恢复。

可交互预览：`design/radio-manager-20261114/index.html`。预览使用隔离模拟数据，不连接设备、不保存到硬件。

## 实现与资源

独立 `radio_catalog.h/.cpp` 管理最多 20 条记录。接口为 `GET/POST /api/radio-stations`，沿用设备热点访问限制；提交采用版本号，区分 400 输入错误、409 版本冲突和 500 存储失败。

目录采用稳定 ID、CRC 校验、临时文件验证、旧版备份和主文件提交。成功落盘后才发布新版本。播放器持有独立字符串快照，后台播放不会引用被编辑或删除的目录内存。原有收藏、最近电台及音量的 NVS 布局保持兼容。

20 条各填满 24 字名称、24 字分类和 512 字节网址时，普通紧凑 JSON 约 14 KB；大量 JSON 转义的极端数据约 24 KB。读取上限 32 KB，已验证极限保存和跨进程恢复。主文件、备份、临时文件峰值低于 0.1 MB。目录固定记录占用 14,792 字节 PSRAM；目录、事务 JSON 和 HTTP 响应均优先使用 PSRAM，减少对音频内部内存的影响。
