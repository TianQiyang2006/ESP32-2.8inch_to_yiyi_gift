# 依依音乐陪伴站

本目录是已部署到 VPS 的实现。早期设计见 `../../MCP音乐陪伴站方案-20261030.md`，以本文件的实际状态为准。

设备使用已修复的 `2.5.0-music` 音乐固件和小智语音云；VPS 提供私有 MP3/LRC 网关、MCP 工具和酷狗音源适配。无需升级到小智最新版。已修复待机后扬声器不启用、Wi-Fi 省电导致下载过慢，以及慢链路发送超时的问题。

## 播放过程

1. 小智调用 `yiyi_music_resolve` 查找本地歌曲；未命中则尝试酷狗准备音源。也可以先用 `yiyi_kugou_search` 选择具体版本，再用 `yiyi_kugou_prepare`。
2. 酷狗实际授权并返回普通音源后，VPS 下载音频，转换为 16kHz、单声道、48kbps MP3，尝试获取 LRC，再发布到私有曲库。接口受限或权限不足时返回失败，不伪装成可播放歌曲。
3. 准备成功后，小智调用设备工具 `self.music.play_song`，设备访问 `/stream_pcm` 获取 MP3 和歌词地址，然后下载、解码和播放。

查询和准备音源不会自行控制扬声器。设备直接点播尚未准备的歌曲会返回未找到，因此智能体应先调用解析工具。

## 现有玩法

- 搜索和准备酷狗音源，查看音源服务状态。
- 只读查看真实酷狗账号歌单，把“我喜欢”等歌单按每批最多5首导入 VPS；仅成功取得完整授权音源的歌曲会进入本地播放歌单。
- 本地收藏、取消收藏、读取收藏，重启后保留。
- 保存偏好、纪念日、专属留言，查询已保存记忆。
- 选择学习、放松、睡眠场景曲目；当前两首原创测试音频已有标签。
- 查询中国标准时间；设备自带音量、亮度、歌词/频谱工具继续使用。

0.4 增加天气、热搜、主动提醒、暂停续播、定时停止和自动连播。酷狗账号登录和单曲播放权限需要分别验证；保存登录令牌不代表全部歌曲可播放。

## 新功能怎么说

| 功能 | 对小智说的例子 | 相关工具 |
| --- | --- | --- |
| 天气 | “查一下天气。”小智先问城市；再答“杭州，看看明天会不会下雨。” | `yiyi_weather`，同名城市返回候选供确认 |
| 热搜 | “播报今天的热搜。”“看看微博热搜前三条。” | `yiyi_hot_news`，综合默认微博和百度，可指定知乎 |
| 主动提醒 | “十分钟后提醒我喝水。”“每天晚上九点提醒我休息。” | `yiyi_current_time` → `yiyi_reminder_create` |
| 查改提醒 | “我有哪些提醒？”“取消刚才的喝水提醒。” | `yiyi_reminders_list` → `yiyi_reminder_cancel` |
| 暂停续播 | “暂停音乐。”“继续播放。” | 设备 `self.music.control` 或 `yiyi_player_control` 的 pause/resume |
| 定时停止 | “半小时后停止音乐。”“取消定时停止。” | `yiyi_player_control` 的 sleep/cancel_sleep，seconds=1800 |
| 建歌单 | “建一个晚安歌单，加入晴天和晚安雨声。”“把这首歌加到晚安歌单。” | `yiyi_playlist_manage`，先准备音源再保存 |
| 连续播放 | “顺序播放晚安歌单。”“循环播放我的收藏。”“下一首。” | `yiyi_playlist_play`、`yiyi_player_control` |

歌单模式支持 `sequence` 顺序一次、`loop` 列表循环、`shuffle` 随机循环、`repeat_one` 单曲循环。收藏可通过 `from_favorites=true` 保存为一个命名歌单。单次准备最多5首，更多歌曲分批追加，每个歌单最多200首。

酷狗账号的“我喜欢”与 VPS 本地收藏是两套数据。先让小智调用 `yiyi_kugou_playlists` 查看歌单，再说“把酷狗我喜欢导入酷狗我喜欢歌单并播放”。`yiyi_kugou_playlist_import` 每次最多准备5首，保持 `batch_size` 不变，按返回的 `next_page` 继续到 `has_more=false`；已导入部分随时可以用 `yiyi_playlist_play` 连播。导入按歌单原始歌曲标识取音源，不用搜索结果替换旧收藏版本；重复导入自动去重，也不会清空原有本地歌单。酷狗账号只进行读取；没有完整播放权限、要求安全验证或只有试听片段的歌曲会跳过并列出原因。每个本地歌单最多200首，VPS缓存有300MB上限。此功能为手动导入快照；酷狗 App 后续增删歌曲不会自动同步。

设备每2秒主动访问私有 `/device/sync`，领取指令并回报执行结果、播放位置和实际结束事件。歌单根据 `ended` 事件切歌，不按预计时长猜测。`queued=true` 仅表示指令已提交；可用 `yiyi_command_result` 确认执行结果，离线指令会过期。

提醒在创建时生成中文语音，保存到 VPS，到了时间设备响铃、显示内容并朗读。语音合成失败时会明确返回 `voice_ready=false`，仍可响铃和显示文字。对话中延后提醒，音乐播放中暂时冻结音乐，播报后继续；手动暂停的音乐保持暂停。提醒和控制依赖设备联网并运行**音乐小智应用 app1**，停在桌面 app0 时不会播报。离线不超过15分钟的提醒会补发，过期提醒不集中补响。工作日按周一至周五计算，不包含法定调休。

暂停保留内存中的解码状态和进度，切换应用或断电后不能接着原位置播放；命名歌单和提醒保存在 VPS，重启后仍在，但不会在设备开机时擅自启动歌单。定时停止一旦送达设备便由本地计时，短暂断网仍能停止；设备重启会清掉本地计时，联网后服务器会补发已经到期的停止指令。热搜结果是标题和链接，播报应注明平台及更新时间，不把标题扩写成未经查询的新闻正文。

播放中先说“你好小智”，等问候结束再说“暂停音乐”等指令。问候后保留约20秒指令窗口；没有继续说话则恢复音乐。手动暂停后，普通对话不会擅自续播，需说“继续播放”。

触屏版音乐固件提供直接操作：进入音乐小智后，点击底部“播放歌单”才会展开歌单列表；列表默认收起，可以点右上角 X 关闭。选择“酷狗我喜欢”或其他已保存歌单后，列表收起并开始顺序播放。播放期间底部显示上一首、暂停/继续、下一首和“歌单”，点击“歌单”才重新显示列表。暂停/继续直接控制设备播放器，保留当前播放位置；上一首、下一首通过私有网关控制当前歌单，单独点播而未启动歌单时会提示没有正在运行的歌单。网络请求在后台执行，无需唤醒小智；切歌需要设备和 VPS 联网，通常等待一次 2 秒轮询及歌曲缓冲。

歌单界面显示 VPS 已导入的歌单快照。“酷狗我喜欢”当前含131首；酷狗 App 后续新增收藏仍需重新导入。触屏控制用于减少播放中唤醒，不代表播放期间的语音回复卡顿已经修复。音乐应用启动音量为40，应用内仍可调节。

网关0.4.2启动歌单时只扫描一次媒体缓存，避免大型歌单逐首扫描曲库导致设备请求超时。设备对私有HTTP指令同步使用12KB内部RAM保留阈值；HTTPS仍使用22KB。播放时约17KB的可用内部RAM可以继续领取切歌指令。

## 服务隔离

部署根目录 `/opt/yiyi-music`，专用用户 `yiyi-music`。仅新增三个 systemd 服务：

| 服务 | 用途 | 监听 |
| --- | --- | --- |
| `yiyi-music` | MP3、LRC、固件查询接口 | TCP 2233 |
| `yiyi-mcp` | 到小智云的出站 WebSocket 桥接 | 无入站端口 |
| `yiyi-kugou` | 酷狗只读接口及扫码授权 | 127.0.0.1:2235 |

没有修改 Caddy、HydroOJ、MongoDB、gost 或 frpc。Node、Python 依赖、FFmpeg 均放在新增目录内，未使用系统 apt 安装。服务有内存、CPU 和权限限制。

- `secrets/config.json`：私有地址配置；固件 `musicurl` 使用其中的 `public_base`。
- `secrets/mcp-endpoint`：小智 MCP 接入点。
- `secrets/kugou-credential.json`：扫码完成后保存的凭据，0600。
- `library/`：原始曲库，包含原创诊断曲《依依的小星光》和《晚安雨声》。
- `data/kugou/`：准备完成的酷狗音频、歌词和原子写入的歌曲索引，缓存预算约 300MB。
- `data/companion.sqlite3`：收藏、专属记忆。
- `data/control.sqlite3`：提醒、命名歌单、指令及设备确认、最近播放状态。
- `data/alerts/`：已合成的短提醒语音 P3/Opus。
- `data/mcp-status.json`：桥接握手、连接状态和云端发现的工具数量。

私有地址及凭据不写进本说明和源码，不要公开 `secrets/`。2233 的 `/health` 仅返回通用健康信息，其余路由需要私有路径。

## 运维

```sh
systemctl status yiyi-music yiyi-mcp yiyi-kugou
journalctl -u yiyi-mcp -n 30 --no-pager
cd /opt/yiyi-music
.venv/bin/python -B test_mcp.py
python3 -B test_gateway.py
.venv/bin/python -B -m unittest -v test_companion test_gateway
```

需要重新扫码时，可由管理员以专用用户运行一次性 `kugou_login.py`，读取 `data/kugou-login.png` 给本人扫描。程序最多等待约 3 分钟，只记录状态，不记录账号令牌。二维码、凭据和账号写操作不作为 MCP 工具暴露。

酷狗适配基于 [MakcRe/KuGouMusicApi](https://github.com/MakcRe/KuGouMusicApi) 1.6.3；`kugou_server.js` 仅加载搜索、普通音源、歌词、二维码登录、账号歌单和歌单歌曲读取模块，不暴露上游项目完整 API，也不提供酷狗账号写操作。Node 使用隔离目录中的 v22.23.4。

## 卡顿修复

音乐播放和下载期间关闭 Wi-Fi 省电，语音通道关闭时也保留此状态；歌曲结束后恢复省电。播放器使用 PSRAM 中的 256KB 缓冲，起播及断流后先积累 64KB。仍有完整 MP3 帧时继续解码，保留分块边界上的数据和文件尾部，停止时等待旧播放线程退出，避免下首歌与旧线程共用解码器。

网关 `0.3.1` 保留请求头的 15 秒超时，媒体传输使用 60 秒发送超时及 8KB 写入块，避免慢链路在一次 64KB 发送中超时截断。仅重启新增的 `yiyi-music` 服务。设备日志每 5 秒报告下载速度、缓冲余量、等待次数和解码错误。
