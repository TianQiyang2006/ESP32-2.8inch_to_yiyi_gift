# 闹钟重构方案 · 2026-11-01

状态：设计已定稿。用户于2026-11-01确认“很好，定稿”。界面、功能预设及三种本地铃声作为后续实施基准，已确认的 App 入口设计保持不变。设计确认不等于固件实施或实板验收；文中新增功能和可靠性要求仍需实施、测试和实板验证。

## 对现有实现的核查

- `hardware/arduino/yiyi_desk/src/pages/focus_page.cpp` 的响铃调用是 `AudioBoard::knock()`，不是音乐铃声。当前没有铃声选择、独立闹铃音量或试听入口。
- `hardware/arduino/yiyi_desk/src/audio_board.cpp` 合成约 60ms 的衰减敲击音，音量与桌面音量共用；桌面音量为 0、音频未就绪或电源保护限制重负载时可能没有声音。
- 当前在主循环内 `FocusApps::poll()` 匹配目标小时和分钟。若整个目标分钟未轮询，没有补响；同一分钟的第一次轮询也不保证落在第 0 秒。
- 当前防重复键只保存在 RAM 中；重启和重新校时时没有完整的持久化去重、漏响与时间跳变处理。
- 北京时间通过 `desk.cpp` 的 `CST-8` 和网络 NTP 配置提供。当前闹钟只用很低的 epoch 门槛判断时间可用，不能代替明确的校时状态。

## 视觉与交互

- 设备画面 320×240。保留米白底、深绿字、浅绿卡片的项目风格。
- 时间数字 34–48px；主标题 18px，主要正文 14–16px。关键信息高对比，不以浅字表示已开启状态。
- 一页只做一件事：列表、时分选择、提醒设置、铃声选择、响铃。主操作区不混放调时、贪睡和重复星期。
- 主要点击区域至少 40×40；底部主操作按钮高 40。星期重复、音量和更多选项在独立页面完成，必要时滚动。
- 列表按下一次响铃时间排列；关闭项目列于启用项目之后。每张卡片显示时间、重复规则、所选铃声、启用开关。
- 时间页分别选择小时 00–23、分钟 00–59，精确到 1 分钟。预览中的滚轮是布局示意，不能当作已实现控件。
- 保存成功后明确显示“下次：11月02日 周一 07:30”这样的绝对日期和时刻；文案按设备实际时间生成。
- 顶部明确区分“已校时”“离线计时”“未校时”。未校时时不展示虚假的下次响铃倒计时。
- 响铃时唤亮屏幕，当前桌面内任何页面都显示响铃层；提供大号“稍后10分钟”和“停止”按钮。

## 功能预设

| 项目 | 设定 |
| --- | --- |
| 数量 | 最多 5 组，各自独立启停、编辑和删除；首次不自动启用任何闹钟 |
| 新建默认 | 07:30、仅一次、经典滴滴、音量60%、贪睡10分钟、最多响铃3分钟、10秒渐强；用户保存并开启后才生效 |
| 重复 | 仅一次、每天、周一至周五、周末、自选星期；“周一至周五”不自动识别法定节假日或调休 |
| 仅一次 | 今天目标时间尚未到则用今天，否则用明天；触发后关闭这条的常规调度，但已安排的本次贪睡仍有效 |
| 时分 | 24小时制，小时和分钟分别选择，分钟步长1，不再使用唯一的±5分钟按钮 |
| 贪睡 | 可选5/10/15分钟，默认10分钟；只在正在响铃时触发。贪睡后显示具体再次响铃时刻，支持取消本次贪睡 |
| 响铃时长 | 可选1/3/5分钟，默认3分钟；超时记录为未处理提醒，不无限播放 |
| 独立音量 | 10–100%，默认60%；不跟随普通点击音量。不得把声音闹钟保存成0%却仍显示“可正常响铃” |
| 渐强 | 默认开启，前10秒从目标音量的20%升至目标值；目标音量仍遵循电源保护 |
| 编辑 | 点击卡片进入；修改先保存在草稿中，取消不改变有效闹钟；关闭或删除条目同时取消其待处理贪睡 |
| 停止 | 停止本次响铃；重复闹钟的下次计划保留 |
| 持久化 | 时间、星期、铃声、独立音量、贪睡时长、开关、最近触发标识；正常重启恢复配置 |
| 无声故障 | 音频不可用或电源保护禁止发声时，不显示“声音就绪”；界面明确报告故障，不绕过电源保护 |

列表截图中两条闹钟仅用于展示多组布局，不是实际写入设备的提醒。第一次新建仍按上述默认值进入草稿。

## 铃声选择

三种本地合成铃声，不依赖 Wi-Fi、音乐平台、账号或网络音频。音频样例由同目录 `make_review.py` 合成，后续固件应使用相同频率、包络和节奏；实板扬声器音色和响度需另行试听确认。

| ID | 名称 | 声音设定 |
| --- | --- | --- |
| classic | 经典滴滴（默认） | 清晰的双音短鸣，880Hz与1175Hz叠加，每轮两声 |
| gentle | 温柔钟声 | 659.25Hz基音加谐波，带衰减的叮咚节奏 |
| progressive | 渐快提醒 | 660/880Hz交替短鸣，间隔在8秒内由约0.75秒缩短到约0.25秒 |

每种铃声都支持“试听”和明确的选中标记。试听使用该条独立音量，最长8秒；离开选择页立即停止试听。正式响铃优先于试听与普通点击声。

## 准时调度与边界处理

1. 单独的后台调度任务检查下一触发时间，目标检查间隔100ms。网络拉取、渲染和切换页面不能成为唯一的检查入口；任务不直接调用LVGL，只向主线程通知界面状态。
2. 按有效的北京时间计算完整的下一次到期时间戳，达到期限即触发，而不是只比较当前时和分。
3. 正常开机、已校时且音频可用条件下，验收目标是**按设备已校准时间，在预定时刻后1秒内开始输出可听见的铃声**。这是待验证目标，不是已取得的实板测量结果。
4. 保存、启停、调整星期、开机恢复和系统校时后都重算下一次到期时刻。重复提醒按日历规则计算，处理跨午夜、周末、月底和跨年。
5. 到期检查跨过目标时刻但延迟不超过60秒时补响一次，并记录延迟；超过60秒记录漏过并计算下一次，不在数小时后突然补响。超过1秒的补响不算通过准时验收。
6. 每次响铃按闹钟ID、目标日期和目标时分形成唯一触发标识并持久化。校时回拨、界面重建和短时间重启不能让已处理的同一次提醒重复响。需要处理持久化写入失败。
7. 贪睡在运行期间使用单调计时，不因NTP校时提前或延后。若要求重启继续贪睡，另保存绝对到期时刻；系统时间尚未恢复时显示等待校时，不能宣称仍可准时提醒。
8. 同时到期的多组闹钟聚合显示，不静默覆盖；停止确认本次这一组同时提醒，贪睡也作用于同组，组内采用最高有效音量和最先到期条目的铃声。
9. 已校时后断网，在设备持续运行时继续使用本地系统时钟，显示最近校时时间。离线晶振漂移需要实板测量，不承诺无限期保持网络时间精度。
10. 关机、掉电、进入不能被定时唤醒的深睡眠，或切到独立小智固件时，不能保证本桌面闹钟执行。没有验证独立RTC及唤醒链路前，产品不得宣称关机闹钟。存在已开启闹钟时，桌面不得自行进入未验证的深睡眠路径。

## 验收清单

- 实板设定未来1–2分钟的闹钟，记录目标时间、任务触发时间与音频开始时间。
- 主界面、其他桌面页面、熄屏、网络更新与渲染负载下分别测试；至少覆盖60次正常触发，逐条核对不漏响、不重复、延迟≤1秒。
- 断网但时间有效、首次尚未校时、重启后恢复、保存失败、音频故障、普通音量为0、低电量保护分别验证。
- 跨午夜、星期切换、周末、月末、年末、仅一次、多个同时提醒、修改与取消进行中的提醒分别验证。
- 模拟NTP前跳、后跳以及轮询跨期，核对补响窗口和去重。60秒补响窗口不是允许正常闹钟延迟60秒。
- 三种铃声选择、试听、独立音量、10秒渐强、音频抢占、停止和自动超时均在实板试听。
- 所有通过结果必须来自实际测试记录；没有这些记录前，只能确认方案和预览，不能确认开发板已经可靠准时响铃。
