# 天气 App 与设备共享数据

`live-data.js` 提供 `window.YiyiData`。第二页天气 App 负责选择城市和获取天气，主页小组件与第二页只引用其快照；不在两个页面分别保存城市或分别查询天气。它已经被打包进独立 HTML 导出。

## 天气来源

地区入口调用 `YiyiData.setCity(city)`。城市不设置固定默认值；变更地区时自动清空旧城市的温度、天气、预报和更新时间。UI 用“未设置城市”或“暂无天气”表示缺少数据。

后续天气 App 注册一次数据适配函数：

```js
YiyiData.setWeatherProvider(async ({city}) => {
  // 在天气 App 中实现这一请求，并把响应映射为下面的统一格式。
  const result = await weatherApp.fetchCurrentAndForecast(city);
  return {
    city,
    condition: result.condition,       // 如“多云”
    temperature: result.temperature,   // 数字，°C
    feelsLike: result.feelsLike ?? null,
    humidity: result.humidity ?? null, // 0～100
    wind: result.wind ?? '',
    low: result.low ?? null,
    high: result.high ?? null,
    sunrise: result.sunrise ?? null,  // 北京时间 HH:MM，如 07:12
    sunset: result.sunset ?? null,    // 北京时间 HH:MM，如 18:00
    pressure: result.pressure ?? null, // hPa
    uv: result.uv ?? null,
    visibility: result.visibility ?? null, // km
    aqi: result.aqi ?? null,
    aqiLabel: result.aqiLabel ?? '', // 可选，留空按 AQI 计算说明
    forecast: result.forecast ?? [], // 最多 7 条 {date,condition,low,high}
    updatedAt: result.updatedAt        // 可选，Unix 毫秒；省略则记录成功收到数据的时间
  };
});
```

上述 `weatherApp.fetchCurrentAndForecast` 是自定义服务的示例入口。当前主预览已注册 `YiyiDevice.weatherProvider`，通过手机连接服务获取 UApi 详细天气；“设置 → 连接手机”中直接输入中文城市并保存，主页与第二页共用结果。电脑预览另保留定位或坐标反查城市的折叠入口。未连接服务时仍可注入标为预览的数据。接入步骤见 [手机连接说明](D:/Tian/给依依的礼物/design/手机连接说明.md)。

注册后，在已选择城市时立即获取；随后每 10 分钟刷新，用户也可在天气 App 手动刷新。一个服务返回只更新一次共享数据。旧地区的延迟响应会被丢弃。刷新失败保留同一城市上次成功的读数及真实更新时间，显示失败原因。缺失湿度、风况和预报不使用固定示例补齐。

七天预报的 `date` 建议提供完整的北京时间日期 `YYYY-MM-DD`，由 UI 自动生成星期，不要仅传星期文字。为兼容已有三天数据，也支持可选 `label`；缺失日期的已知预报按 `updatedAt` 对应日期解释，“今天 / 明天 / 后天”分别为 0 / 1 / 2 天，其他条目默认从下一天开始。提供的日期不会随页面跨天被改写；不足七条时只为缺少的读数显示占位。

日出日落采用 24 小时制；没有数据时传 `null`，不能用 00:00 代表未知。温度、紫外线、能见度、湿度与 AQI 的 0 都是有效读数。修改城市时以上所有指标和预报一起清除，等待新地区数据。

如果天气 App 已有自己的获取周期，也可直接推送完整结果，不注册额外轮询：

```js
YiyiData.updateWeather({
  city: currentCity,
  condition: currentCondition,
  temperature: currentTemperature,
  updatedAt: observationTimestamp,
  source: 'device'
});
```

读取 `YiyiData.getWeather()`；结果是副本。新 App 可用 `YiyiData.subscribe(({type,value}) => { ... })` 订阅 `weather`、`battery`、`clock`，返回的函数取消订阅。注入设计示例时使用 `source: 'preview'`，不当作实际天气。

## 时间与日历

`YiyiData.time()` 返回北京时间的 `clock`、日期 `key`、年月日、星期及英文星期；`YiyiData.now()` 返回共享时钟的 Date。所有页面使用这些数据，时钟每秒通知一次；重新显示浏览器页面时也立即刷新。

后续设备完成 NTP 或主控校时后调用 `YiyiData.syncTime(epochMilliseconds)`，之后按实际经过时间继续走时。设计工具关闭实时走时后，同一时钟使用指定的预览日期时间，倒计时也跟随此时间。

跨天更新今天的标记；日历当前跟随今天时跨月切到新月份，手动选择的其他日期及浏览月份保留。天气、电量或时钟更新只改对应显示，不刷新正在编辑的表单。切到留言、倒计时、日常或应用页时共享数据继续更新，返回即显示最新状态。三种全屏钟面也读取此时钟，山水背景根据北京时间切换六个时段。

## 电池接口与已核对电路

采样任务推送：

```js
YiyiData.updateBattery({
  present: true,
  percent: estimatedPercent, // 0～100；尚无有效读数时为 null
  charging: null            // true=确认充电；false=确认未充电；null=无法判断
});
```

电池缺席时推送 `{present:false,percent:null,charging:null}`。读取 `YiyiData.getBattery()`；`low` 由“电池存在、读数有效且 ≤20%”统一计算，0% 仍是有效低电量。充电与低电量可同时显示，不用电压上涨推断正在充电。

根据 [开发板硬件原理图](D:/Tian/给依依的礼物/开发资料/2.8inch_ESP32-S3显示模块硬件原理图.pdf) 核对：

- 板上有 TP4054 充电电路，电池端为 BAT+ / GND。
- BAT+ 经 R14 / R15 两个 200 kΩ 电阻作 1:1 分压，BAT_ADC 接 ESP32-S3 GPIO9。电池电压约为校准后 ADC 电压的 2 倍；固件还需平均采样及针对电池的电量估算。
- 图中 TP4054 的 CHRG 经 R11 接 GND，没有连接主控 GPIO；VBUS 也未画出独立的主控检测输入。因此接入电池可使用板载充电电路，但只凭现有 GPIO9 采样无法可靠确认充电、USB 是否接入或电池是否实际存在。

后续真实充电指示需提供可读取的 CHRG / 供电状态信号；未接入该信号时推送 `charging:null`。HTML 中的百分比、充电和低电量控制用于预览，未执行硬件采样或烧录。

## 星期与节日共享计算

`YiyiHolidayCalendar.read(YiyiData.time(), config.holiday)` 返回 `remaining`、中文问题与状态、英文星期、目标公历日期及 `newYear / springFestival` 的 `{date, days}`。`holiday.weekday` 使用 0=周日至 6=周六，`holiday.label` 是用户设定的日历文字；默认 5 / 放假。页面、缩略图和独立 HTML 都调用同一个模块，不各自保存剩余天数。

固件或后续主控只需通过 `YiyiData.syncTime(epochMilliseconds)` 校准共享时钟；日历、每周目标、元旦、春节、第四页日期及日历内自定义倒计时随后持续更新。无需逐页写星期或天数。关闭实时走时使用主页设定的预览日期，便于检查跨天和节日边界。

春节离线数据范围与来源见 [日期数据说明](D:/Tian/给依依的礼物/design/calendar-data-source.md)。超出支持范围返回未知；每周目标不推算国家法定调休安排。

## 心情、木鱼与喝水

`YiyiDaily` 统一处理第五页日常记录，时间来自 `YiyiData`：

```js
YiyiDaily.saveMood(YiyiDaily.today(), 'happy', '今天的小事');
YiyiDaily.strike();
YiyiDaily.addWater(200);
YiyiDaily.undoWater();
const current = YiyiDaily.summary(); // 今日量、目标、百分比、次数与累计次数
const week = YiyiDaily.week();       // 本周一至周日；含确切日期、今天、未来标记
```

`dailyRecords[date]` 的结构为 `{mood, note, knocks, water:[{amount,at}]}`。饮水时间 `at` 为统一时钟的 Unix 毫秒，`amount` 为整数 ml。读取历史用 `day(date)`，序列化用 `snapshot()`；删除心情不删除同日木鱼与饮水。`daily` 保存每日目标、声音及页面外观。工作台收到日常变更立即持久化，并同步到缩略图；独立 HTML 使用自己的本地运行状态。

这层目前服务于 HTML 交互；后续硬件接入时可复用相同日期键与记录格式，不向每个页面分别写计数。原自定义倒计时保留在日历应用，第六页独立留言，第七页应用与设置；相册已移除。应用参数可从手机保存并同步。


## 名言与诗句共享数据

`reading-data.js` 暴露 `window.YiyiReading`，两张卡片和缩略图统一读取这一层：

```js
YiyiReading.read('quote'); // text / author / source / date / updatedAt / loading / error
YiyiReading.read('poem');  // 另含 title / dynasty，text 为全文
await YiyiReading.refresh('quote');
await YiyiReading.refresh('poem');
const cache = YiyiReading.snapshot();
```

`reading` 保存自动更新开关、接口/手动模式、手动文字与颜色；`readingCache.quote / poem` 各保存 `{text,author,title,dynasty,date,updatedAt,source:'api',provider}`，新缓存的 `provider` 分别为 `uapis`、`palemoky`，旧缓存允许缺省。`date` 和 `updatedAt` 为成功请求时的共享日期/时间；一言读取 `https://uapis.cn/api/v1/saying` 的根字段 `text`，作者留空；诗词读取 `https://poetry.palemoky.com/api/poems/random?lang=zh-Hans` 的 `data.content` 全文及作者、标题、朝代。API 元数据不另行猜测。旧的一言缓存即使日期是今天也会尝试迁移到新接口，失败保留缓存。缩略图禁止请求，由主预览向工作台发送缓存，再同步到缩略图。

`file://` 预览的一言请求走现有本地手机服务 `/api/reading/quote`，它只转发固定的 UApi 一言地址，保留 HTTP 错误码和 `Retry-After`。HTTP 预览与固件直接请求上游 API。

`configure(options, cache, {enabled})` 用于配置/导入，`ensure()` 按共享日期检查每日更新；同接口合并进行中的请求，超时 10 秒，刷新冷却 10 秒，429 遵守 Retry-After（最短 60 秒）。配置改变或跨日后的旧响应不会覆盖新内容。失败不清空缓存，也不改成功时间；`source` 明确区分 `api`、`manual` 和 `example`。

独立 HTML 内嵌模块与缓存，可离线阅读；后续成功更新写入它自己的本地运行状态。工作台撤销设计及恢复初始设计保留接口缓存和日常记录。

## 留言板与三张便签

`message-board.js` 引用统一配置与共享日记，不另起天气或时钟请求：

- “今日心情”读取 `YiyiDaily.day(YiyiDaily.today())`，日期来自 `YiyiData.time()`。详情打开时记录正在阅读的日期，跨天不替换该日记；返回后便签显示新的当天记录。
- “想对你说”引用原 `letter:{title,text,signature}`，旧配置直接保留。
- “留个小纪念”使用新增 `keepsake:{title,text,signature,date}`；正文最多 3000 字，标题与落款最多 80 字，可选日期为有效的 1900～2099 年 `YYYY-MM-DD`。空正文表示未记录，不补入示例。

手机连接服务的 `phone-save` / `device-sync` 支持 `keepsake` patch，与 `letter` 独立合并。模型校验后同步到当前页、缩略图及工作台保存；独立 HTML 的运行缓存也包含纪念内容。阅读时的其他参数更新保留滚动位置，实际正文变化则显示最新内容。

图层升级标记为 `messageStyle:'sticky-board-v1'`，只迁移第六页旧纸条布局，不清空留言或日记。验证：`node tools/design-review/check-message-board.cjs` 和 `python tools/design-review/check-phone-server.py`。
