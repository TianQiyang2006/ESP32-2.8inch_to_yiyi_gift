# 已确认设计与当前实机的差异 · 2026-11-01

用户反馈：“现在的ui和设计和预定不一样呢”。核对属实。当前刷入的是旧界面上的闹钟存储恢复补丁，不是已确认界面的完整实现版本。

| 区域 | 已确认设计/方案 | 当前实机 |
| --- | --- | --- |
| App分页 | 第一页6个App，第二页闹钟和番茄时钟 | 8个App同屏，4列2行 |
| 新App图标 | 使用用户提供并已纳入预览的图标 | 使用铃铛/播放符号 |
| App文字 | 两页统一字号和样式，无新增遮罩；小智AI文字与图标保持间距 | 旧卡片、小字号和旧图标文字位置 |
| 闹钟 | 已定稿的5组闹钟列表、时间选择、设置、铃声选择及响铃页 | 旧的单组闹钟页，使用±5分钟按钮和星期按钮 |
| 铃声 | 3种本地预设的设计/试听样本 | 原有 `AudioBoard::knock()` 发声路径，预设未接入 |
| 番茄时钟 | 重构预览方案，尚待完整确认与接入 | 原有简单单页 |

## 原因与检查遗漏

- 定稿资产和清单保存在 `design/`；闹钟清单的 `implementation_status` 实际仍为 `pending`。
- 实际App运行布局来自 `hardware/arduino/yiyi_desk/src/gift_ui.cpp` 的 `appsPage()`，仍按4列创建8个入口；闹钟运行界面来自 `src/pages/focus_page.cpp` 的旧 `buildAlarm()`。
- 之前检查的是设计文件未被改动、补丁测试和编译成功。刷入前后的旧界面截图也相同，但没有把目标固件的实际渲染与已确认设计逐页对照。这是本次交付版本核对的遗漏。
- 已确认的界面布局和资源继续作为实现基准，不重新设计；当前没有获得再次刷入其他版本的确认。

## 设备当前状态

- 已刷入闹钟保存补丁，并完成镜像及完整闪存读回校验。
- 原音乐固件、NVS、分区表和文件系统在刷入时保持不变。
- 临时测试时间08:05已恢复为原来的08:00，闹钟保持关闭；未继续重启保存测试。
- 定稿新界面、多闹钟、预设铃声仍未完成固件接入；不能把当前实机作为设计验收通过。

## 后续版本的验收基准

先对照已确认文件完成固件实现，再生成与实际固件同源的逐页预览，明确列出功能接入和存储空间检查结果。用户确认具体版本后才能再次刷入，不能以设计文件哈希不变代替固件界面一致性检查。
